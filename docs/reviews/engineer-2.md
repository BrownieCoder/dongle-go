## 缺陷与关闭证据

| 初审问题 | 复审结果 |
|---|---|
| P1：已有同设备快照的 usbnet 改为 `broken` 后，apply 仍写入成功，随后无法 restore | 新建、载入、内存快照均严格校验 schema 与字段。原独立脚本重跑报 `invalid_snapshot`，模式仍为 0，关闭 |
| P1：第二次打开相同端口时替换模块，曾向 replacement 执行模式 1 写入 | 实际写入 handle 内重读完整状态、核对前后枚举身份。原脚本现在报 `identity_mismatch`，replacement 写入列表为空，关闭 |
| P2：当前模式 99 可以成为无法恢复的基线 | 诊断解析拒绝范围外模式，回归证明无快照、无写入，关闭 |
| P2：原子替换后未同步父目录 | POSIX 路径增加目录 fsync；同步失败注入阻断写入，关闭。未宣称真实掉电试验通过 |
| P2：快照写失败遗留临时文件，使下次保存永久失败 | finally 只清理本次独占创建且设备号/inode 一致的非 symlink 临时文件；故障后重试通过，预存 symlink 防护仍通过，关闭 |

成功恢复后会退役原快照，避免永久阻塞后续模块。传输层读写时间与响应大小有界、部分写入或超时污染通道后拒绝继续、完整 ERROR 允许受控继续。USB 配置与重启始终拒绝；严格候选描述符检查不等同真机已认证。实际白名单为空，不因候选 VID/PID 或演示结果授予真实写权限。

隐私检查：原始 AT 响应不被日志输出；公开 UI 错误不含响应正文；APN 不返回给 UI、不写快照。恢复文件保留最小设备绑定字段并使用 0600 创建，不能把含序列号的恢复文件直接放入公开报告。未执行 Windows ACL 实测。
