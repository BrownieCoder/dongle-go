## 发现与交付缺口

1. **P2：恢复错误误导。** `error_key` 的子串匹配将 `invalid_snapshot` 和 `snapshot_failed` 均归为“本次会话没有恢复记录”，无法区分损坏备份和保存失败。`identity_mismatch`、`recovery_pending`、`read_only_transport` 也只提示通用重试。底层拒绝危险写入，但用户缺少正确下一步。已反馈实现者；需精确映射和回归测试。
2. **P2：发现提示未同步 USB 诊断。** 空列表中英文仍称“未找到支持的串口连接”，与已实现的 USB 发现不一致。已反馈实现者。
3. **分发证据不足。** CI 构建文件正确地只上传预览 artifact，不发布 release；但尚无冻结程序启动验证。需要有界、无硬件 smoke，确认 Tk 与打包 libusb 可加载，并在目标系统运行。macOS 本地通过也不能当作 Windows 通过。
4. **文档检查遗漏。** `scripts/check_docs.py` 不扫描 `THIRD_PARTY_NOTICES.md` 和 `licenses/README.md`，漏掉前者指向尚不存在的 `docs/assets.md`。英文图片正在生成，初审时 README 图链确实不存在。
5. **量表区分不足。** 初审时 `docs/acceptance.md` 仅有包含真机证据的正式交付量表，不能将它与本报告的软件 30/25/25/20 量表混算。需明确两种结论。
